# V3 研究引用校验定向修复

## 已确认边界

- 只修改 `personal-agent` 当前 `master`，保留已有未提交改动，不提交或推送。
- 不修改 `personal-os`、真实资产、历史研究任务、模型预算或运行配置。
- 不调用真实模型，不自动重跑研究，不新增单元测试文件，不自动重启现用服务。

## 已知事实与限制

- 真实任务 `review_e4f104389894293c7501e9e6` 在三次模型调用后失败，累计使用
  28,485 Token。最后的过滤步骤丢弃一项内容，报判断缺项和缺少有效核验支持。
- 构造数据可以复现：一条原本存在、但引用无效的核验条目被过滤删除，最终错误变成
  判断缺项，原始引用错误丢失。这证明诊断链路有缺陷，不证明真实草稿必然相同。
- 真实失败未保存过滤前草稿，不能据此还原模型原始输出。本轮不伪称已复现真实返回。

## 方案

1. 区分“条目存在”与“条目有效”。引用错误必须定位到条目下标、字段及无效引用，
   不能把无效条目当作模型没有返回，也不能据此允许判断变更。
2. 过滤只清理不可信证据候选和判断修改建议，不再删除或自动补写逐项核验条目。
   过滤后继续严格校验；不合格的核验必须失败关闭。
3. 综合、修复请求根据实际提供的摘录与有效候选生成引用清单，包含已授权数值引用。
   修复同时获得具体错误位置、准确引用清单和有界 Schema；不能猜测引用对应关系，
   不能把既有引用编号改绑到另一段原文，不能伪造 supported，也不能通过增加调用
   次数或预算来掩盖协议问题。
4. 保留过滤前、过滤后的必要校验原因和丢弃数量。诊断限量、脱敏，不保存原始模型
   草稿、个人上下文或报告正文，不写入 durable 资产。

## 验收

- 扩展既有协议验收，构造“有效候选 + 无效核验引用 + 有效判断修改”路径。
- 覆盖原始引用错误保留、真实漏项、无效引用不可支持判断变更、数值引用及安全的
  部分结果保留，不把删除条目或自动降级为 unresolved 当成修复成功。
- 用真实 DeepSeek 客户端配假 HTTP 响应，验证实际发出的修复请求含完整错误、引用
  清单和 Schema，并覆盖修复成功、修复失败；所有网络出口均被替身拦截。
- 执行既有服务、隐私、架构与模型客户端测试；必要时复用现有跨仓隔离验收，所有
  API、SQLite、资产仓及模型响应都是临时或构造数据。

## 验证结果

- 现有 Agent 协议验收通过，扩展了经真实 DeepSeek 适配器、假 HTTP 出口的六种
  三阶段路径：修复成功、引用持续无效、引用改名、引用改绑、真实漏项、数值部分结果。
  实际请求包含错误位置、同一判断清单、完整引用目录和对应 Schema。
- 无效核验引用不会变成漏项，不能支持判断修改，也不会被自动删除、补齐或降级。
  仅可选证据候选或修改建议被安全丢弃时，保留前后诊断并标注部分结果。
- 空引用目录、直接数值引用、诊断限量与密钥脱敏通过；没有真实模型请求。
- 既有服务、隐私、架构和模型客户端测试共 54 项通过。
- 使用现有 Go API 构建执行跨仓隔离验收通过，覆盖股票、基金、引用写回、部分结果、
  提交恢复、重复结果复用与显式重跑；没有修改 `personal-os` 源码。
- 真实资产 HEAD 保持 `c3c46e09fbb38804a880cad6f0edbd6782484b9f`，工作区状态未变；

- 未重启后台、未重装 App、未执行完整 UI E2E，未提交或推送。
  本轮证明引用/诊断协议的离线路径正确，不代表真实模型复查已经成功；
